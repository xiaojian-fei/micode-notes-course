# 模拟器环境修复说明（未维护基线）

本文记录在 **未维护基线 `1fa9ebb`** 上实际遇到的两个环境问题、原因与处理方式，供其他组员在自己电脑上复用。
两项问题**都不是源码缺陷**，不需要修改 `src/`、`res/` 或 `build.gradle`，处理动作全部发生在模拟器侧。

相关脚本：[`scripts/fix-emulator-env.ps1`](../scripts/fix-emulator-env.ps1)

---

## 1. 新建便签无法保存

### 现象

- 基线安装、启动正常，能点开"＋ Add note"，能输入文字。
- 按返回回到列表后，**便签没有出现**；重复操作仍然保存失败。
- 界面不报错，只有 logcat 里能看到异常。

### 定位

```powershell
adb -s emulator-5554 logcat -d -t 300 | findstr /C:"SQLite"
```

关键输出：

```text
W AsyncQuery: Exception thrown during handling EVENT_ARG_QUERY
W AsyncQuery: android.database.sqlite.SQLiteException: Can't downgrade database from version 5 to 4
```

### 原因

- 维护版（main）把数据库升到了 **version 5**，并新增了置顶字段 `pinned`。
- 未维护基线 `1fa9ebb` 的 `NotesDatabaseHelper` 中 `DB_VERSION = 4`。
- 在同一个模拟器里先装过维护版、再装基线时，`adb install -r` **保留原有应用数据**，基线打开这份 version 5 的库即触发 SQLite 降级保护，所有写入失败。

也就是说：**这不是基线编译或运行的问题，而是设备上残留了更高版本的数据库。**

### 处理

```powershell
adb -s emulator-5554 shell pm clear net.micode.notes
adb -s emulator-5554 shell am start -n net.micode.notes/.ui.NotesListActivity
```

清除后基线会重新创建 version 4 数据库，新建、保存、返回列表、重新打开、修改后重开均恢复正常。

### 验证

```powershell
# 1) 重新操作一次新建与保存，列表应出现该便签
# 2) 取回数据库核对版本与记录
adb -s emulator-5554 shell run-as net.micode.notes cp /data/data/net.micode.notes/databases/note.db /sdcard/Download/note.db
adb -s emulator-5554 shell run-as net.micode.notes cp /data/data/net.micode.notes/databases/note.db-wal /sdcard/Download/note.db-wal
adb -s emulator-5554 pull /sdcard/Download/note.db
adb -s emulator-5554 pull /sdcard/Download/note.db-wal
# 用任意 sqlite 客户端打开 note.db：PRAGMA user_version 应为 4，note 表应存在新记录
```

> 该库使用 WAL 模式，只复制 `note.db` 而不复制 `note.db-wal` 时可能看不到最新表结构或记录。

### 注意

- `pm clear` **会删除模拟器内该应用的全部便签**。仅在确认没有需要保留的测试数据时执行。
- 想彻底避免该问题：给基线使用**全新的模拟器**，不要与维护版共用同一台设备。
- 反之，如果先装基线、后装维护版，是升级路径（4 → 5），不会报错。

## 2. 无法输入中文

### 现象

- 编辑便签时键盘只有英文，输入法切换不到中文。
- 长按输入框也无中文输入法可选。

### 原因

模拟器镜像默认输入法是英文 Gboard，可用输入法列表里只有：

```text
com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME
com.google.android.googlequicksearchbox/com.google.android.voicesearch.ime.VoiceInputMethodService
```

### 处理

API 28 的 `google_apis` 镜像**自带谷歌拼音输入法**（`/system/app/GooglePinyinIME`），只是默认未启用：

```powershell
adb -s emulator-5554 shell ime enable com.google.android.inputmethod.pinyin/.PinyinIME
adb -s emulator-5554 shell ime set    com.google.android.inputmethod.pinyin/.PinyinIME
```

首次启用后切到编辑框，会出现"允许谷歌拼音访问通讯录"的权限弹窗，按需允许或拒绝，之后即可用拼音选字输入中文。

### 验证

在编辑框输入 `bizijian`，候选栏应出现"鼻子见 / 鼻子 / 比 / 笔 / 必"等候选词，说明拼音输入已生效。

### 备选

若镜像内确实没有拼音输入法，可安装开源输入法 Trime（同文），其发布页提供 **x86_64 独立包**，与模拟器架构匹配：

```text
https://github.com/osfans/trime/releases
```

安装后同样用 `ime enable` / `ime set` 启用（服务名为 `com.osfans.trime/.ime.core.TrimeInputMethodService`）。

## 3. 保存操作的正常流程（避免误判为无法保存）

参考 [使用指南第3节](使用指南.md)：

1. 编辑完成后按返回键。
2. 如果只是收起了键盘，**再按一次**，直到回到便签列表。
3. 在列表点开该便签确认内容保留。
4. 修改后同样返回到列表并重新打开检查。

空白便签会被忽略，不产生记录。因此"输入为空 + 直接返回"看起来也像"保存失败"，实际是设计行为。
