# 小米便签队友独立记录与分工

更新日期为2026年11月12日。本文件可直接转发给毕子健和梁冠杰。按费枭健当前说明，开发和本地回归已完成，两人现在各自完成独立环境搭建、原版编译运行和个人记录。以下均为待执行任务，完成后按实际结果填写。

## 1. 老师要求的“独立记录”是什么

课程指导书明确要求：

- 每位成员有明确、可核查的分工，封面如实填写。
- **每位成员独立完成一次环境搭建，并成功编译运行原版软件。**
- 保留报错与解决记录、静态分析报告、Gradle日志、Git提交等过程材料。

因此，每位队友至少需要在自己实际使用的电脑上完成：

**配置环境 → 编译未维护基线 → 安装启动 → 做基本操作 → 保存本次日志和截图。**

只安装组长已经编译好的APK，不能证明自己成功编译；把组长的截图或日志改名，也不能当个人独立记录。源码、安装包和操作方法可以共享。

每人在自己的电脑上执行第5节，并交齐第6节材料。已有源码、报告和操作说明可以共用，个人日志、截图及报错解决记录由本人实际执行产生。

## 4. 正确认识三个版本

| 版本 | 用途 |
| --- | --- |
| `1fa9ebb` | 本地环境适配后的未维护基线，供个人“原版运行”记录；尚无本次4+3功能。提交说明已注明是根据标注前快照补录，不冒充上游原始提交历史 |
| `b706753` | 第3章标注后版本，供核对代码标注 |

这里“原版”指保留原有业务功能、做过必要构建兼容适配的课程基线，不表示2014年上游源码未经任何适配就能在新SDK下编译。

main是维护版，不能用main的置顶/筛选界面冒充原版。`代码标注记录/标注前源码.zip` 只包含源码快照，不是可独立构建的完整Gradle工程。

## 5. 每人怎样完成环境与原版运行记录

### 5.1 安装或确认工具

建议沿用已实测的组合：

- JDK 17；项目原实测版本为17.0.12，记录自己的实际版本。
- Git。
- Android SDK Platform 34、Build Tools 34.0.0、Platform Tools。
- Android Emulator和Android 9 / API 28的x86_64镜像。若自己的设备不同，记录实际API，不能照抄28。
- Gradle 8.7由仓库Wrapper提供；Android Gradle Plugin为8.4.0。

可用Android Studio管理SDK和模拟器，也可以用命令行工具。SDK安装位置在SDK Manager中查看；具体入口见[Android官方SDK Manager说明](https://developer.android.com/studio/intro/update#sdk-manager)。使用IDE时注意Gradle JDK与本项目的JDK 17要求一致。

### 5.2 创建两个独立工程目录

以下路径是示例，选择自己有权限、空间足够的目录。已有同名工程先核对，不覆盖或强行重置。

```powershell
New-Item -ItemType Directory -Path 'C:\se-lab' -Force | Out-Null
Set-Location 'C:\se-lab'
git clone https://github.com/xiaojian-fei/micode-notes-course.git
Set-Location 'C:\se-lab\micode-notes-course'
git worktree add --detach '..\micode-notes-baseline' 1fa9ebb
```

结果：

```text
C:\se-lab\micode-notes-course\       维护工程，包含Gradle Wrapper
C:\se-lab\micode-notes-baseline\     未维护基线，独立工作目录
```

旧基线没有Wrapper，下文使用维护工程的Wrapper指定基线目录构建；这只提供构建工具，不把维护版业务源码混进基线。

### 5.3 设置自己机器的环境并建立记录目录

**先把JDK、SDK路径换成自己电脑上的真实目录。** 不要照抄组长的D盘路径。

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-17'       # 示例：替换为实际JDK 17目录
$env:ANDROID_HOME = 'C:\Android\Sdk'    # 示例：替换为实际SDK目录
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:Path = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:Path"

# 在自己的电脑建立本次个人记录；目录名可以改为本人姓名。
$recordRoot = 'C:\se-lab\个人记录'
New-Item -ItemType Directory -Path $recordRoot -Force | Out-Null
New-Item -ItemType Directory -Path (Join-Path $recordRoot 'screenshots') -Force | Out-Null

Get-Date -Format o | Out-File (Join-Path $recordRoot '环境信息.txt') -Encoding utf8
java -version 2>&1 | Out-File (Join-Path $recordRoot '环境信息.txt') -Append -Encoding utf8
git --version | Out-File (Join-Path $recordRoot '环境信息.txt') -Append -Encoding utf8
git -C 'C:\se-lab\micode-notes-baseline' rev-parse HEAD |
    Out-File (Join-Path $recordRoot '基线commit.txt') -Encoding utf8
```

重新测试时使用新目录或带日期的新文件名，不覆盖已有失败记录。记录目录名字本身不是执行证据，还要有实际输出和对应截图。

### 5.4 自己构建原版基线

```powershell
Set-Location 'C:\se-lab\micode-notes-baseline'
& '..\micode-notes-course\gradlew.bat' -p . --console=plain assembleDebug 2>&1 |
    Tee-Object -FilePath (Join-Path $recordRoot '原版构建日志.txt')
if ($LASTEXITCODE -ne 0) { throw '基线编译失败，保留日志并先解决问题。' }
```

首次会下载Gradle和依赖。以实际日志中的 `BUILD SUCCESSFUL` 和生成APK为依据，截图保留成功结尾及项目路径。失败后记录报错、处理方法和重试结果；如果一路成功，写“本次未遇到构建错误”，不用人为制造报错。

### 5.5 安装、启动并实际操作原版

先通过 Android Studio 的 Device Manager 创建并启动自己的新模拟器，再执行下列命令。使用新设备可避免旧版基线覆盖已有维护版数据。

```powershell
adb devices
$serial = 'emulator-5554'   # 改成实际设备号

adb -s $serial shell getprop ro.build.version.release |
    Out-File (Join-Path $recordRoot '设备信息.txt') -Encoding utf8
adb -s $serial shell getprop ro.build.version.sdk |
    Out-File (Join-Path $recordRoot '设备信息.txt') -Append -Encoding utf8
adb -s $serial shell date |
    Out-File (Join-Path $recordRoot '设备信息.txt') -Append -Encoding utf8
adb -s $serial shell getprop persist.sys.timezone |
    Out-File (Join-Path $recordRoot '设备信息.txt') -Append -Encoding utf8

adb -s $serial install -r 'C:\se-lab\micode-notes-baseline\build\outputs\apk\debug\MiCodeNotes-debug.apk' 2>&1 |
    Tee-Object -FilePath (Join-Path $recordRoot '原版安装日志.txt')
if ($LASTEXITCODE -ne 0) { throw '安装失败，先核对签名和设备，不自动卸载应用。' }
adb -s $serial shell am start -n net.micode.notes/.ui.NotesListActivity
```

在UI上完成：

1. 显示原版列表。
2. 新建一条只用于本次测试的便签，输入自己的测试文本。
3. 返回，再打开，确认内容保留。
4. 修改并保存，再次打开确认，保留这条测试便签。正文建议包含本人姓名、实际日期和“原版运行测试”。

至少留下：构建成功、原版首页、编辑内容、返回后重新打开四个关键画面。截图可用系统截图，也可用ADB（每张使用不同文件名）：

```powershell
adb -s $serial shell screencap -p /sdcard/Download/01-baseline-home.png
adb -s $serial pull /sdcard/Download/01-baseline-home.png (Join-Path $recordRoot 'screenshots\01-baseline-home.png')
```

使用设备文件后再 `pull`，可避开旧版PowerShell将二进制重定向写坏的问题。后续截图把文件名改为02、03等，不反复覆盖第一张。

```text

├── 个人实验记录.md
├── 环境信息.txt
├── 设备信息.txt
├── 基线commit.txt

    ├── 00-build-success.png
    ├── 01-baseline-home.png
```

### 可以复制的个人记录模板

下面是待填模板，**实际执行后填写**，不要预先把结果写成通过。

```markdown
# 个人实验记录

## 基本信息

- 姓名、学号：待填写
- 实际日期：待填写
- 本次承担任务：独立环境搭建、原版编译运行、个人运行记录整理
- 操作系统、JDK版本及路径：待填写
- Android SDK及模拟器版本/API：待填写
- 设备号与时区：待填写
- 原版基线完整commit：待填写

## 原版编译与运行

1. 环境配置过程：待填写
2. 执行的构建命令：待填写
3. 构建实际结果及日志路径：待填写
4. 安装、启动、新建、保存及重新打开结果：待填写
5. 截图文件及其观察点：待填写

## 报错与解决

- 实际报错、日志及尝试：待填写；未遇到报错则如实说明
- 仍未解决的问题：待填写

## 发现的问题及反馈

- 实际现象、版本、复现步骤及证据：待填写；未发现问题则如实说明

## 本次实际完成与未完成

- 实际完成：待填写
- 失败或未验证：待填写
- 给组长的材料清单：待填写
- 个人收获：结合自己实际操作简要写几句
```

个人记录不是再写一份完整六章报告；说明做了什么、版本是什么、结果在哪里即可。个人收获可用于合并第6章，具体篇幅以老师要求为准。
